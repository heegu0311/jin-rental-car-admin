# 홈 팝업 드래그 정렬

2026-11-07. 이벤트 목록의 ‘홈 팝업 순서’에서 드래그 후 ‘순서 저장’을 누른다. 모바일·키보드는 위/아래 버튼을 이용한다. ‘되돌리기’는 마지막 저장 순서를 복원한다. 숫자를 직접 입력하는 필드는 없다.

- 검색·필터와 별개로 전체 `is_popup` 이벤트를 정렬한다. 비공개·기간 외 이벤트도 순서는 보존하며 고객 웹에서는 기존 공개 조건으로 걸러진다.
- 저장 전에는 변경 안내를 표시하고, 중복 제출을 차단한다. 실패해도 미저장 순서를 유지한다. 목록이 다른 작업으로 바뀌면 서버가 전체 ID 일치를 확인해 저장을 거부하며 새로고침을 안내한다.
- 성공 시 고객 웹 재검증을 요청한다. 즉시 반영 실패는 기존 최대 3시간 지연 안내를 유지한다.
- 이벤트 일반 저장은 서버 세션 + `profiles.role` + 기존 RLS로 검증한다. 제목·주소·기간·boolean을 검증하고, 정렬 필드는 일반 편집에서 덮어쓰지 않는다. 수정 페이지에서 `is_popup` 초기값이 빠졌던 문제도 수정했다.

## DB 적용

소유: admin. 연결 프로젝트 `daerwmqweobyeecbquuh`가 앱 URL과 일치함을 확인한 뒤 아래 파일만 CLI `db query --linked --file`로 적용하고 `migration repair --status applied`로 이력을 기록했다.

- `20261107053444_event_popup_order.sql`: `events.popup_order integer NOT NULL DEFAULT 0`, 0~9999 제약. 기존 이벤트 내용·상태·기간·순서를 유지한다.
- `20261107054005_reorder_event_popups.sql`: `reorder_event_popups(uuid[])`. SECURITY INVOKER + 빈 search_path. 함수 내부에서도 관리자 프로필을 확인하고 기존 RLS를 유지한다. 익명 EXECUTE는 금지하며 authenticated만 호출 가능하다. 전체 목록 검사와 순서 UPDATE를 잠금이 있는 한 트랜잭션에서 처리한다.
- 웹은 `popup_order ASC, created_at DESC, id DESC`로 읽는다. 컬럼 적용 전 환경에서는 해당 컬럼 없음 오류에만 기존 최신순으로 대체한다.
- 신규 팝업은 기본 0으로 추가된다. 필요하면 목록에서 원하는 위치로 이동해 저장한다.

## 검증

- web/admin `pnpm exec tsc --noEmit`, `pnpm lint`, `pnpm build`, web `pnpm test` 34개/admin 29개 통과.
- 1440px·390px 로컬 브라우저에서 실제 HTML 드래그(1,2,3→2,3,1), 위로 이동, 되돌리기, 저장 버튼 활성/비활성과 문서 가로 넘침 없음을 확인했다. 임시 UI는 검증 후 삭제했다. 로그인한 관리자의 브라우저 저장 테스트 대신 UI 검증과 아래 실제 DB 트랜잭션 검증을 분리했다.
- DB 임시 테이블로 순서·동일 순서 최신순 및 범위 제약을 확인하고 롤백했다. 실제 팝업 목록은 관리자 JWT 컨텍스트 + authenticated 역할에서 함수 호출·결과 순서·중복/빈 배열 거부·비관리자 거부를 확인한 후 전체 트랜잭션을 롤백했다. 운영 순서·updated_at 변경은 남기지 않았다.
- 익명 함수 실행 불가, authenticated 실행 가능, SECURITY DEFINER 아님을 조회했다. CLI 보안 advisor error 수준은 문제 없음.
- 웹 공개 키의 실제 팝업 API 조회는 성공(3개), 정렬 오름차순 확인. 운영 이벤트를 테스트 예시로 대체하지 않았다.
- 고객 웹의 긴 이미지도 함께 수정했다. 800×3200 이미지·두 줄 제목으로 1440×900 / 390×844 / 1440×600 / 390×600에서 팝업 세로 스크롤 없음과 상세 링크·인디케이터 표시를 확인했다. 스크린샷은 web/artifacts/event-popup/fit-*.png.

DB 변경은 적용 완료. 외부 코드 push·웹/admin 배포는 수행하지 않았다.
